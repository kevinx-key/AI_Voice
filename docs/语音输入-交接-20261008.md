## 2. 本轮（2026-10-07/08）做了什么

### 2.1 第7轮：热键链路架构修复 + 可观测性

**根因（实测确认）**：低级钩子在 **CPU 被 LLM 吃满**时会漏掉 KEYUP → `KEY_DOWN` 卡在 true
→ **之后每一次 F9 按下都被当成"自动重复"静默丢弃（零日志）** → 用户体感"按了热键没反应"。
（Bug1 与 Bug2 是同一个根因。假设"GPU 抢渲染卡住 GUI"**不是**根因，但 GUI 确实会卡，见 §4。）

**5 处修复**（`src/hotkey/windows.rs` + `src/main.rs` + `src/gui.rs`）：

| # | 改动 | 作用 |
|---|------|------|
| 1 | **热键转发独立线程** `hotkey-relay`（原在 `Gui::pump`，eframe 帧里） | 热键与 GUI 渲染彻底解耦 |
| 2 | **回调内自愈**：`KEY_DOWN==true && !is_key_down(vk)` → 复位并当新按下处理 | 根治：从"吞掉后续数秒所有按下"降到"最多影响丢 KEYUP 那一次" |
| 3 | **钩子重装零间隙**：先装新钩子、再摘旧钩子 | 消除 60s 重装时的丢键窗口 |
| 4 | 自检节拍 5s→2s；钩子线程 `THREAD_PRIORITY_HIGHEST` | 抗 CPU 饥饿 |
| 5 | **埋点**：`HOOK_CALLS`/`HOOK_VK_CALLS`/`KEYUP_SELFHEAL` 心跳 + `钩子→转发滞后 Xms` + `钩子→worker 滞后 Yms` + GUI 帧间隔看门狗 | 补上"钩子被静默摘除"这个唯一零日志盲区 |

## 7. 坑与纪律（**新会话务必先读这一节**）

1. **日志按 UTC 轮转**：文件名是 `app.log.<UTC日期>`。本地 08:00 前，UTC 日期还是"昨天"。
2. **对账必须逐进程**：`PRESS_SEQ` 是进程内静态，**每次重启都从 1 开始**。跨进程做集合比较会产生假阳性/假阴性（这次就踩过）。用 `tools\log_audit.py`。
3. **E2E 前必须停 listen**：fork（WeaselServer）会在输入法激活时**自动把装机版拉回来**，`Stop-Process` 后要**立刻**跑 E2E，否则被它抢先。
4. **两条 grep 覆盖不了"按下"**：worker 受理一次按下有**三条**合法日志 —— `热键按下 seq=`、`会话中再次按下 seq=`、`切换模式：再次按下 seq=`（第 3 条是本次补的）。
5. **`--simulate` 与真实会话判据曾经不一致**（它用 `rms < min_speech_rms`）—— 已抽共用函数 `segment_verdict()`。**不要让基线跑在会分叉的代码路径上**。
6. **改完必须装机验证**，不能只看编译通过（项目纪律）。
7. **文档回落规则**：`调试计划.md` 只写未来；`项目调试过程.md` 只写过程与证据；`README.md` 是门面（功能/配置变了必须同步）。
8. **隐私红线**：微信聊天原始数据（`D:\work-summary\.data`、`D:\xwechat_files` 等）**禁止云端模型读写**，只允许本地 llama.cpp 管线。护栏：`~/.pi/agent/extensions/privacy-guard.ts`。
9. **GUI/llama-server 抢 GPU**：GUI 走 wgpu 且选中 RTX 5070 Ti（`Cargo.toml:14` 的 eframe 是 `wgpu` 特性，README 旧文写的"glow"是错的，已更正）。`ngl=99` 时整理期间 GUI 会定格 1~3.4s。
10. **本机没有 Audacity/ffmpeg/sox**；Win10「录音机」只能存 m4a → 用 `listen.exe --record`。
11. **噪声样本必须按住 >3 秒**：`RING_SECONDS=3.0`，旧 `--record` 只在松手后取一次 →
    超过 3s 的部分被覆盖，样本全部卡在恒 3.00s、开头整段丢（**已修**，`tools\check_record_fix.py` 守着）。
12. **`--gate` 的 `segs=0` 不等于「拦住了」**：尾段被证据闸丢弃的那档现在单列 `tail_dropped`；
    真正要看的是 **`asr_segs`（送 ASR 段数）= 幻觉暴露面**。2026-10-08 前这个数看不见，
    导致键盘噪声段「全部进了 ASR」被误读成「被拦住了」。
13. **看到「有按下没落点」先查那个进程是不是旧二进制**：第 8 轮前的 build 在 toggle 停止支路**无日志**
    （表现为“按了没反应”）。`log_audit.py` 已修掉“空进程也开新 run”的分段缺陷，标签现在是对的。
14. **WARP（`gui_render = "software"`）是禁区，别当“安全选项”**：它确实能彻底避开独显争用，但实测
    隐藏时 3.17 个核、窗口可见时 16 个核（单帧约 1 CPU 秒）。默认 `auto` 是**集显优先**，
    本机没有集显 → 仍走独显。要改默认值先看《项目调试过程.md》§19.3 的实测表。
15. **分层透明窗（悬浮窗）不可用合成截图判定**：独显与 WARP 两张图的背景完全一样，
    说明 `CopyFromScreen` 抓不到分层窗口内容 → 只能真人肉眼确认一次。同时：
    **设置窗聚焦时按 F9 不响应**（Windows 跳过“输入目标是钩子进程自己窗口”的键盘事件），
    所以截悬浮窗要静默启动 + 合成 F9（`tools\shot_ui.py` 已按此实现）。
16. **"界面卡 / 定格"类问题先用基准复现再动手**：`python tools\gui_stall_bench.py` 五阶段全 0 次，
    就说明成因不在本进程，改渲染参数是白忙（§19 就是这么把四个嫌疑人逐个验掉的）。
17. **本机是 200% 缩放（AppliedDPI=192）**：任何 PowerShell/C# 截图脚本**必须先 `SetProcessDPIAware()`**，
    否则 `Screen.Bounds` 与 `CopyFromScreen` 用虚拟化坐标 → 截出来的区域完全错位。
    （踩过两次：一次把悬浮窗背景当成“渲染空白”，一次把托盘区截成一片灰。分辨率会报成 1920x1080，实际 3840x2160。）
18. **托管模式下“托盘”要分清两个**：listen.exe 自己的**状态色点**（`managed_tray`，默认开，录音=红）
    vs fork/Weasel 的**输入法图标**（受 Rime 配置 `display_tray_icon` 控制，本机为 **false** → 那个图标压根不存在）。
    “托盘不变红”的排查第一步就是确认到底有没有那个图标（截图/数图标个数）。
19. **改协议要往后加字段**：`ListenCtl STATUS` 的前 4 个字段（state/mode/backend/polish）**已冻结**，
    fork 按序号读且兼容更短回复；新增一律接在最后（`recording|idle` 就是第 5 个）。
20. **管道协议里的时间戳不能带 `:`**（2026-10-09）：`HH:MM:SS` 自带两个冒号，会把组内字段序号全部移错。
    现在 `CHAIN` 里时刻写成无分隔数字（`234444`），含 `:` 的**尾字段**（窗口标题/关麦原因）用 `splitn` 吃掉剩余。
21. **强杀持流的进程后紧接着开新流，会拿到一段“全是 0”的流**（`flowing` 仍为 true，
    而 `--record` 只录到 0.31s 全零）；等一会儿再录就正常（实测 5.32s → RMS 0.00069）。
    → 卡片的「有块但电平恒为 0 = 数字静音」判定就是为了这个（不要一看 0.0000 就以为“麦坏了”）。
22. **只改注释也会换可执行文件 SHA** → 改完必须重编重装，别拿旧 SHA 对账。
23. **ListenCtl 管道现在始终启动**（不再限托管模式）：独立运行（双击 exe）时 `--status`/fork 的“在不在跑”才能拿到真相；
    单实例互斥体保证不会有两个服务端。

## 8. 已知限制（**出现以下现象不要报为 bug**）

| 现象 | 原因 |
|---|---|
| 焦点在**本程序设置窗**上时按 F9 不响应 | Windows 对"输入目标是钩子进程自己的窗口"跳过钩子；设置窗隐藏到托盘即正常 |
