## 0. 一句话目标

WeaselServer（倾听输入法引擎）成为**唯一常驻宿主**；语音 listen.exe 变为**受管子进程**：
切到倾听输入法 → 自动启动/恢复；切到其他输入法 → 挂起（释放内存）；5 分钟无激活 → 自动退出。
托盘与入口收敛为一个，语音不再"一直挂着"。

## 2. 设计

### 2.1 架构（目标态）

```
┌─ 目标应用进程（任意 app）─────────────┐
│  weaselx64.dll（TSF in-proc，必须保留）│
└──────────────┬────────────────────────┘
               │ WeaselNamedPipe（现有）
┌──────────────▼──────────────────────────────────────┐
│ WeaselServer.exe（唯一常驻宿主 = 倾听输入法）           │
│  · Rime 引擎（键盘输入，现状不动）                      │
│  · 激活状态判定（新）→ 控制管道 → listen 生命周期（新）  │
│  · 托盘（唯一）：语音输入子菜单 + 设置入口（扩展）        │
└──────────────┬──────────────────────────────────────┘
               │ \\.\pipe\ListenCtl（新，行协议）
┌──────────────▼──────────────────────────────────────┐
│ listen.exe（受管语音进程，按需存活）                    │
│  · --managed：不建托盘；收 suspend/resume/命令          │
│  · 挂起：摘热键钩子 + 卸 ASR 模型（释放内存）            │
│  · 5 分钟无 resume → 自退；切回 → fork 拉起/唤醒         │
└─────────────────────────────────────────────────────┘
```

### 2.2 IME 激活检测（fork 侧，本任务最关键）

- **接线 OnActivated**：QueryInterface 暴露 `IID_ITfActiveLanguageProfileNotifySink` + ActivateEx 里 `AdviseSink` + Deactivate 里 `Unadvise`（注册模式照抄 ThreadMgrEventSink.cpp:38-51）
- **per-thread 状态机**：`{focused, active}`；"用户正在用倾听输入法" = 存在 `focused && active` 的线程
  - FocusIn(tid)/FocusOut(tid) 更新 focused（已有链路）
  - OnActivated(tid, TRUE/FALSE) 更新 active
- **防抖**：状态翻转后 **2s** 确认再下发（避免快速切换抖动）
- **兜底链**（若 OnActivated 在某些应用/线程不触发）：
  1. `Deactivate()`（WeaselTSF.cpp:97，EndSession）视为切走
  2. 再兜底：listen 侧轮询前台线程输入配置（HKL/TSF profile），连续 3 次非本输入法 → 自行挂起

### 2.3 控制协议（fork → listen）

- **载体**：命名管道 `\\.\pipe\ListenCtl`（行协议，UTF-8，`\\.\pipe\` 自动按用户会话隔离）
- **命令**：`PING` / `STATUS` / `SUSPEND` / `RESUME` / `SHOW_SETTINGS` / `SET backend <local|cloud>` / `SET polish <tier>` / `SET hotkey_mode <hold|toggle>` / `QUIT`
- **生命周期归属**：fork 判定 active 且 listen 未运行 → `spawn listen.exe --managed`（普通用户身份，复用 App Paths 定位逻辑 WeaselUtility.h:197-245）；inactive → `SUSPEND`；listen 自计时 5 分钟 → 退出
- **配置新增**（config.rs `[general]`）：`managed_suspend_exit_minutes = 5`（0 = 不自动退）
- **模式语义**：`--managed` 由 fork 传入；手动从开始菜单启动 = 独立模式（现有托盘形态，开发/无 IME 可用）

### 2.4 挂起/恢复（listen 侧）

| 动作 | 内容 |
|------|------|
| SUSPEND | 停当前会话 → 摘热键钩子 → `drop` ASR recognizer（释放几百 MB）→ 状态回 Idle；设置窗可继续开 |
| RESUME | 重装钩子 → 异步重载模型（就绪前热键按下给"启动中"提示，不丢按键） |
| 超时退出 | suspend 后启动 5 分钟定时器，未 RESUME → `process::exit(0)` |
| 设置窗 | 不受挂起影响；fork 的「倾听输入法 设置」继续走 `--settings`/`Global\ListenShow`（已实现） |

### 2.5 托盘合并（fork 侧）

- 新子菜单「语音输入」：`状态（只读，如 就绪/已挂起/未运行）` / `录音方式（按住|切换）` / `识别后端（本地|云端）` / `文本整理（5 档）` / `打开倾听输入法设置` / `退出语音`
- 子菜单实现：`CreatePopupMenu()` + `InsertMenuItemW(..., MIIM_SUBMENU, ...)`（项目内无现成模式，照 Win32 标准写法）
- 新菜单 ID 从 **40018** 起（40017 已用）；命令经 `ListenCtl` 转发；勾选状态在 `CustomizeMenu` 时用 `STATUS` 快速查询（100ms 超时，失败显示"未运行"）
- listen 托管模式**不再创建托盘**（复用 `--no-tray` 代码路径）

## 4. 验收标准

| # | 场景 | 期望 |
|---|------|------|
| 1 | 登录后，未使用倾听输入法 | 无 listen 进程（任务管理器中只有 WeaselServer） |
| 2 | 切到倾听输入法 | listen 自动启动、模型就绪（<3s） |
| 3 | 切到其他输入法 | ≤2s 内挂起：模型内存释放、热键失效、托盘状态变「已挂起」 |
| 4 | 挂起 5 分钟未切回 | listen 自动退出（进程消失） |
| 5 | 5 分钟内切回 | 秒级恢复（不重新加载模型） |
| 6 | 托盘 | 全系统只有一个倾听输入法托盘；语音菜单项可用、勾选正确 |
| 7 | 键盘功能 | 打字/候选/F4 切方案/Ctrl+Shift+4 简繁 全程不受影响 |
| 8 | 独立启动 listen.exe（无 --managed） | 现有行为不变（自持托盘，开发用） |
| 9 | 语音热键语义 | 仅在倾听输入法为当前输入法时可用（设计意图，写进 README） |

## 5. 风险与回退

| 风险 | 对策 |
|------|------|
| OnActivated 触发行为与应用/线程相关 | 三层兜底（Deactivate → listen 轮询 HKL）；先在常见 app（记事本/浏览器/微信/VS Code）实测覆盖 |
| 快速切换抖动导致反复挂起/恢复 | 2s 防抖；恢复失败自动重试一次 |
| fork spawn listen 失败（权限/路径） | 日志 + 托盘气泡提示；回退独立模式可手动启动 |
| 挂起残留（钩子/会话未清） | SUSPEND 路径单测 + 状态日志断言 |
| 托盘状态查询阻塞 UI | 100ms 超时 + 缓存上次状态 |
| **总回退** | 不传 `--managed` 即退回现状（listen 独立常驻），零损失 |
