## 0. 一句话目标

把倾听输入法的**中文拼音输入质量**从"词频统计 + n-gram"提升到**接近微信输入法的语境级体验**——优先补"语义排序 / 联想 / 词库"三块，守住"本地优先 + 隐私红线"，明确放弃不可追平项（云端亿级数据画像）。

## 1. 背景与差距（详见评估报告）

- 我们 = librime 1.13.1 + 雾凇拼音(rime_ice, 43MB 词库) + 万象 400MB n-gram；微信 = 云端神经 LM + 亿级数据 + 跨源个性化。
- 本质：**词频统计 vs 语境理解**。
- 可逼近：语义级排序、词库规模/新鲜度、联想/纠错。
- 不可追平：云端数据、跨源画像、跨设备同步（隐私/架构决定）。
- 被低估的资产：万象 n-gram（已装未调优）、本机 Qwen3.5-4B/llama-server（现仅用于润色）、已编译未启用的 `predict` 插件。

## 3. 阶段计划（任务清单）

> 每任务含：做法 / 涉及文件 / 产出 / 验收 / 风险。**做完一阶段出一次安装包并装机验证**。

### 阶段 P0 —— A 层：配置 + 词库（1–3 天，低风险）

#### S0 基线测量（**先做，不可跳过**）
- 做法：建固定测试集（常用句 50 + 长句 30 + 领域句 20），脚本喂拼音串（`listen.exe` 无此功能 → 用 `librime` 的 `rime_api_console` 或 WeaselDeployer 的调试命令，或写一个小 Rust/CLI 走 `script_translator`），记录**首选命中率 / 前 5 命中率 / 长句正确率 / 平均候选位置**。
- 涉及：新建 `tools\pinyin_bench\`（含测试集 + 跑分脚本）。
- 产出：`baseline-YYYYMMDD.json` + 报告段落。
- 验收：可重复跑出稳定分数。
- 风险：Rime 无现成 CLI → 可能需用 `librime` 的 `rime_console` 或 WeaselDeployer 调试模式；先探路。

#### S1 打开联想 / 上下文建议
- 做法：`rime_ice.custom.yaml` 的 managed 块加 `translator/contextual_suggestions: true`（必要时配 `contextual_suggestions_max_length`）；评估是否启用 `predict` 插件（schema `engine` 加 `predictor` + `predictor:` 段）。
- 涉及：`src\rime\schemes.rs`（生成 patch 的 block）、`resources\rime\schemes\rime-ice\rime_ice.schema.yaml`。
- 产出：新安装包；对比 S0 分数。
- 验收：候选窗出现上下文联想；首选/长句分不降。
- 风险：联想项过多干扰 → 可调 `max_homophones`/排序。

#### S2 模糊音 + corrector 调优
- 做法：`rime_ice.custom.yaml` 加 `speller/algebra` derive 规则（zh/z、ch/c、sh/s、n/l、an/ang、en/eng、in/ing、ian/iang、uan/uang…按需）；`corrector` 的 `spelling_hints` 按需；喂自定义错词表。
- 涉及：`src\rime\schemes.rs`、rime-ice 的 patch 示例。
- 产出：安装包 + S0 对比（重点看"打字容错"用例）。
- 验收：模糊音用例命中率↑；重码干扰可控。
- 风险：模糊音增加重码，个别常用输入变慢 → 可只开部分规则。

#### S3 词库扩容 v1
- 做法：抓 1–2 个主流细胞词库（搜狗/腾讯），转 `*.dict.yaml`，与 `cn_dicts\base|ext|tencent` 合并去重赋权，`librime` 编译。
- 涉及：`cn_dicts\*.dict.yaml`、`src\rime\mod.rs`（OUR_SCHEMA_IDS/清单）、打包体积。
- 产出：词库体积 43MB → ~80–120MB；安装包变大。
- 验收：新词/长尾词覆盖率↑；S0 首选命中率↑。
- 风险：体积/编译时间/版权来源（用公开细胞词库，注意许可）。

#### S4 自定义短语 / 热词注入
- 做法：整理常用句/术语/口头禅，灌 `custom_phrase.txt`（rime-ice 的 `custom_phrase` 翻译器）；可选：你的领域词（键盘/嵌入式）。
- 涉及：`resources\rime\schemes\rime-ice\custom_phrase.txt`（或我们的 patch）。
- 产出：安装包。
- 验收：常用短语一键上屏。
- 风险：无。

### 阶段 P1 —— B 层：工程化（1–3 周，中风险）

#### S5 词库工具链 + 更新机制
- 做法：写"抓取→转换→合并去重→赋权→编译"脚本；加版本号；设置页加"更新词库"入口（离线优先，可打包增量）。
- 涉及：新建 `tools\dict_build\`；`src\rime\`；`gui.rs` 设置页。
- 产出：一键更新词库 + 可发布的词库包。
- 验收：更新后 S0 分数不降且新词覆盖↑。
- 风险：来源稳定性/许可。

#### S6 个性化（本地）
- 做法：一键导入自定义词/热词；把"用户选过的词"回流本地词典（Rime userdb 已有，增强权重自适应）；可选通讯录/术语表导入（本地解析）。
- 涉及：`src\rime\`、`gui.rs`、配置项。
- 产出：个性化导入 UI + 本地学习增强。
- 验收：常用人名词/专有词位置前移。
- 风险：隐私（**全本地**，不得上云）。

#### S7 场景化权重（可选）
- 做法：TSF 侧拿前台进程名 → 通过约定/管道告知 listen/rime → 切换词库权重 profile（微信/IDE/浏览器）。
- 涉及：`K:\K3R-voice\WeaselTSF`（前台进程）、`ListenCtl`/config、rime patch 切换。
- 产出：场景 profile。
- 验收：不同场景首选更贴合。
- 风险：复杂度/兼容。

#### S8 librime 升级评估（对应 Q1）
- 做法：评估升到 ≥1.17，解锁 `max_sentences`、`dictionary_exclude` 等；在独立分支重编 fork（Boost/librime/插件），回归验证。
- 涉及：`K:\K3R-voice\librime`、`K:\Libraries\weasel_build*.bat`。
- 产出：升级版 fork（若可行）。
- 验收：原有功能不回归；新特性可用。
- 风险：**构建链回归风险高**，单独立项验证。

### 阶段 P2 —— C 层：架构（1–2 月，追平关键）

#### S9 LLM 重排 · 离线验证（对应 Q2/Q3）
- 做法：拿本机 Qwen3.5-4B 做**离线批测**：对 S0 测试集的每个拼音串，Rime 出 top-N 候选 → 连同上文交给 LLM 按语境重排 → 对比首选命中率提升。参考 llm-ime（本地 GGUF 重排候选）。
- 涉及：新建 `tools\llm_rerank_proto\`（可 Python + 现有 llama-server HTTP）。
- 产出：`rerank-eval.json` + 结论（是否值得上实时）。
- 验收：首选命中率有**明确提升**（定阈值，如 ≥+15%）。
- 风险：LLM 抖动、prompt 设计；离线不计延迟。

#### S10 小模型常驻重排 MVP（若 S9 有效）
- 做法：配 0.5B~1.5B 量化模型常驻（或复用 llama-server 换小模型）；**按句/停顿触发**（不逐键）；结果异步回填候选窗。
- 涉及：`llm_server.rs`、`polish.rs` 旁路新模块 `rerank.rs`、Rime↔重排的桥（候选读取/回填）。
- 产出：实时重排 MVP。
- 验收：延迟 <150ms；S0 分数提升接近 S9 离线值。
- 风险：**延迟**（核心风险）、候选窗回填的工程改造。

#### S11 候选窗异步回填 / UI
- 做法：把重排结果异步写回候选窗（Rime 候选刷新有限 → 可能需在 Weasel/WeaselPanel 层做，或先只对"首选置顶"）。
- 涉及：`K:\K3R-voice\WeaselUI\WeaselPanel.cpp`、`WeaselTSF`。
- 产出：重排在 UI 可见。
- 验收：无闪烁/无输入阻断。
- 风险：TSF/UI 改造面大。

#### S12（可选）神经 LM 整句 / 云端 LR
- 做法：用（量化）Transformer LM 替换/叠加 n-gram 做整句 beam 重排；或云端 LR（**只传拼音串**，需单独授权）。
- 验收：长句质量接近商用。
- 风险：模型体积/延迟；云端涉及隐私授权。

| 约束 | 说明 |

## 5. 基线测量（S0 是前提）

- **测试集**：`tools\pinyin_bench\cases.tsv`（拼音 \t 期望首词），分常用/长句/领域三组。

- **跑法**：优先复用 `librime` 自带的 console/调试能力；无则写最小 CLI（Rust 或 C++ 链接 librime）。
- **用途**：每个阶段做完都跑一遍，**只有分数上升才算有效**。
