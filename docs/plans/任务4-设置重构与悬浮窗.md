## 2. 设计

### 2.2 外观主题（新增，需先 spike 生效机制）

- 写入 `%APPDATA%\Rime\weasel.custom.yaml` 的**我们管理块**（沿用标记块机制，卸载可摘）：
  `style/color_scheme`、`style/font_face`、`style/font_point`、`style/inline_preedit`、`style/label_format` 等
- 主题清单来源：Weasel 内置配色 + 方案包附带（扫描 `data\preview` 或 weasel 内置列表）

- 预览：设置页内嵌缩略预览（v1 可只做下拉选择 + 说明文字）

### 2.3 悬浮窗（本任务核心体验）

**形态**

- 无边框、置顶、半透明小窗；圆角深色底 + 状态色点（复用托盘状态色）
- 默认**不穿透**（可拖动、可点右上角关闭本次显示）；设置项「鼠标穿透」开启后 `with_mouse_passthrough(true)`
- 位置：默认**当前显示器底部居中**；拖动后记忆（config 存坐标 + 显示器标识）；多显示器按会话开始时的前台窗口所在屏
- 生命周期：会话开始出现 → 会话结束延迟 **1.5s** 隐藏；挂起/待机不显示

**内容（v1）**

```
● 识别中  00:37   ▁▂▄▆▃▂   本次 128 字
「我觉得这个 nRF52832 的 SAADC 采样有点问题」
```

- 状态点 + 文案：录音中 / 识别中 / 整理中 / 注入中 / 错误（state.rs 直接映射）
- 计时：会话时长（Recording 起算）
- 音量条：RMS 实时（新事件，节流 ~10Hz）
- 最新一段识别文字：段完成即刷新（默认 25s 段；可调小 `segment_seconds` 到 8~10s 换更快刷新，设置页给提示）
- 累计字数：本次会话已注入字数

**技术实现**

- 同一 listen 进程内用 eframe viewport：`ViewportBuilder::with_decorations(false).with_always_on_top().with_transparent(true).with_taskbar(false)`；优先 `show_viewport_immediate`（简单），若与主窗/托盘消息循环冲突再评估 `deferred`
- **新增事件**（main.rs `Evt`）：
  - `Evt::Segment { text: String, seq: u32 }`：`process_segment` 识别完成时发送（main.rs:523-530 处）
  - `Evt::Level(f32)`：音频 drain 处发送，节流 ~10Hz
  - （可选）`Evt::Session { active: bool }`：会话起止
- GUI `pump`（gui.rs:205-231）消费事件 → 更新悬浮窗状态；窗口在 Idle 且无新事件时不重绘（省 CPU）
- 与任务2 的挂起联动：SUSPEND 时立即隐藏悬浮窗

### 2.4 托盘/入口统一（承接任务2，不重复实施）

- 单托盘（fork 承载）：`语音输入` 子菜单（状态/录音方式/后端/整理档/退出语音）+ `输入法` 子菜单（设置/高级/重新部署）+ 通用项
- listen 托管模式不建托盘；独立模式保留现有托盘
- 本任务只做**菜单项文案/分组打磨**与「高级」入口归位

## 4. 验收标准

| # | 场景 | 期望 |
|---|------|------|
| 1 | 按住 F9 说话 | 悬浮窗立即出现：录音中 → 识别中 → 注入中 状态实时；计时走动；音量条随说话跳动 |
| 2 | 一段识别完成 | 悬浮窗刷新该段文字（默认 25s；段长调 8s 后明显更快） |
| 3 | 会话结束 | 1.5s 后自动隐藏，无残留窗口 |
| 4 | 拖动悬浮窗 | 位置记忆，下次会话同位置出现 |
| 5 | 鼠标穿透开启 | 悬浮窗不挡鼠标操作；关闭后可拖动 |
| 6 | 多显示器/缩放 | 主副屏、125%/150% 下位置与清晰度正常 |
| 7 | 设置中心 | 状态卡信息正确；语音/输入法高频项齐全；「高级」能打开 4 个原生窗 |
| 8 | 外观主题切换 | 生效（按 spike 结论的轻量路径）；简繁/打字不受影响 |
| 9 | 托盘 | 单托盘菜单分组清晰；勾选与设置一致（任务2 验收项 6 复查） |
| 10 | 挂起联动 | 切走输入法 → 悬浮窗立即隐藏；切回恢复显示 |

## 5. 风险与对策

| 风险 | 对策 |
|------|------|
| eframe 多视口与托盘/winit 消息循环冲突 | S2 先在开发机 spike（immediate 优先）；冲突则退化方案：独立 Win32 分层窗口线程（`WS_EX_LAYERED`，不依赖 egui） |
| 悬浮窗遮挡输入/抢焦点 | 默认 `with_taskbar(false)`、不激活焦点（`with_active(false)` 或 `Focus(false)` 控制）；位置默认底部居中 + 透明度 |
| "实时"预期落差（SenseVoice 非流式） | 状态真实时；文字按段；设置页给"段长换刷新速度"提示；真流式（zipformer streaming 中英）列二期评估 |
| 主题生效需要慢部署 | spike 找轻量路径；必须部署时异步 + 进度提示 |
| 事件流新增影响性能 | `Level` 节流 10Hz；`Segment` 仅段完成时；GUI 空闲不重绘 |
| 大改 UI 回归风险 | config.toml 字段不动（纯 UI 重组）；分步验收（悬浮窗与设置中心解耦） |
