### 2.1 懒加载首次触发的行为（我的推荐，明天可直接采纳）

冷启动 llama-server 约 **10~30s**。若首次整理时同步等待，用户说完话要干等半分钟，体验很差。

**推荐行为**：

```
第一次触发整理
  → 后台 spawn llama-server（不阻塞）
  → 本次直接注入 ASR 原文（不等）
  → 托盘/GUI 提示「本地大模型启动中，本次未整理」
  → 就绪后（通常 30s 内）后续自动使用本地整理
```

即：**首次降级、不等待**。若希望改为「本次等待」，改 `[polish.local] wait_on_first_use = true` 即可。

`K:\AI_Voice\app\polisher.py`（108 行，已验收）关键点：

## 4. 设计

### 4.1 新增模块 `src/llm_server.rs`

```rust
/// llama-server 生命周期管理（懒加载 + 复用 + 可选回收）
pub struct LlamaServer {
    exe: PathBuf,
    model: PathBuf,
    host: String,
    port: u16,
    ngl: i32,
    ctx: u32,
    start_timeout: Duration,
    log_path: PathBuf,
    child: Mutex<Option<std::process::Child>>, // 仅自己拉起的才非 None
}

impl LlamaServer {
    pub fn new(cfg: &LocalLlm, paths: &Paths) -> Self;

    /// GET /health，200 = 就绪
    pub fn alive(&self) -> bool;

    /// 已在跑 → 复用；否则 spawn 并轮询就绪。**不阻塞调用方超过 start_timeout**
    pub fn ensure_started(&self) -> Result<bool>;   // Ok(false)=本次没起来

    /// 后台异步启动（懒加载首次用，不等待）
    pub fn spawn_background(self: &Arc<Self>);

    /// 只回收自己拉起的进程
    pub fn stop(&self);
}
```

要点：
- `child` 用 `Mutex<Option<Child>>` 因为 `stop()` 需要 `&self`（在 `Drop`/退出路径调用）
- 复用判定必须**先于** spawn，避免和已运行的实例抢端口
- 端口被占但 `/health` 不通 → 报错「端口被占用且不是 llama-server」，提示改端口

### 4.4 `src/polish.rs` 改造

```rust
pub struct LocalPolisher {
    server: Arc<LlamaServer>,
    system: String,          // 复用现有 PROMPT_LIGHT / PROMPT_POLISH
    temperature: f32,
    top_p: f32,
    max_tokens: u32,
    disable_thinking: bool,
    timeout: Duration,
}

impl Polisher for LocalPolisher {
    fn name(&self) -> &str { "本地大模型" }
    fn polish(&self, text: &str) -> Result<String> {
        // 1. alive()? 否 → 首次：spawn_background()，返回 Err("本地模型启动中") → 调用方回退原文
        // 2. POST /v1/chat/completions（含 chat_template_kwargs）
        // 3. 剥 <think>...</think> 兜底
    }
}
```

`build_polisher()` 按 `(enabled, provider, mode)` 分发：

```rust
match (cfg.polish.enabled, cfg.polish.provider.as_str()) {
    (false, _)          => Box::new(NoopPolisher),
    (true, "local")     => Box::new(LocalPolisher::new(...)),   // 需要 Arc<LlamaServer>（跨线程共享）
    (true, _)           => Box::new(CloudPolisher::new(...)),
}
```

`LlamaServer` 实例由 `Worker` 持有（`Arc`），退出时回收。

### 4.5 退出回收（决策 3）

两条退出路径都要覆盖：

| 路径 | 处理 |
|------|------|
| GUI「退出程序」/ 托盘「退出」 | `Cmd::Quit` → worker 收到 → `server.stop()` → `process::exit(0)` |
| 窗口被系统关闭 / 进程被杀 | `LlamaServer::drop()` 里做最后一次 `stop()`（`stop_on_exit=true` 时） |

> 注意：`stop()` 只在 `child.is_some()` 时生效，**绝不会杀掉用户手动启动或别的程序拉起的实例**。

## B3. 架构与文件布局

### B3.1 进程模型

| 进程 | 职责 | 生命周期 |
|------|------|---------|
| `WeaselServer.exe` | Rime 输入法引擎（TSF），键盘输入本体 | 系统级常驻，独立于 ai-voice |
| `WeaselDeployer.exe` | 部署/编译词库（向导在首启和换语言时调用） | 一次性 |
| `ai-voice.exe` | 语音输入 + 托盘 + 设置界面（含「输入法」页，兼作首启向导） | 用户级常驻 |

### B3.2 硬约束（设计红线）

1. **不把 Rime 塞进 ai-voice 进程**——TSF 架构决定，只能做交付层/界面层/配置层合并
2. **方案包必须全部放 Rime 用户目录的独立子目录**（不散落根目录），卸载才能干净摘除
3. **`default.custom.yaml` 只 patch 我们管理的键**，已有文件必须合并（追加语义），**不整文件覆盖**；写入前先备份 `.bak`
4. 用户自己的 `*.custom.yaml`、`*.userdb\`、`build\` 一律不动

### B3.3 目录布局

安装目录（Inno Setup 默认 `{autopf}\AIVoice`）：

```
ai-voice.exe
resources\
  rime\
    weasel-0.17.4.0-installer.exe     # 小狼毫官方安装器（锁定版本）
    schemes\rime-ice\                 # 雾凇拼音
    schemes\easy_en\
    schemes\hangul\
    schemes\jaroomaji\
    lm\wanxiang-*.gram                # 万象语法模型
```

Rime 用户目录 `%APPDATA%\Rime`（小狼毫默认；自定义 userdir 需检测）：

```
rime-ice\  easy_en\  hangul\  jaroomaji\  lm\   ← 我们铺的（卸载时删）
default.custom.yaml                            ← 我们管理的键（卸载时摘除）
<用户自己的> *.custom.yaml / *.userdb\ / build\ ← 一律不动
```

仓库新增（`resources/` 不入库）：

```
src\rime\mod.rs            # RimeInstaller：检测/安装/铺包/写配置/部署/卸载

tools\verify_rime.ps1      # 文件层自动化校验
resources\                 # gitignore
```

## B5. 首启向导流程（时序）

```
1. Inno Setup 安装完成
   → 检测小狼毫：注册表 Uninstall 项 / 安装目录 / WeaselServer.exe 存在性
   → 未装：静默安装 weasel-0.17.4.0-installer.exe /S（锁定版本）
   → 已装：跳过，记录版本（低于要求则提示）
2. 铺 ai-voice.exe + resources\
3. 拉起 ai-voice.exe --first-run
4. egui 向导页：选主力语言（中/英/日/韩）+ 可选开关（英文混输默认开）
5. 写配置：
   → 复制对应方案包到 Rime 用户目录（已存在则跳过/增量更新）
   → 合并写 default.custom.yaml（schema_list + 开关；写入前 .bak 备份）
   → 记录 config.toml [rime].primary_lang / weasel_installed_by_us
6. 调 WeaselDeployer.exe /deploy（界面提示「正在部署，首次可能需要几分钟」）
   → 轮询部署完成（部署产物 / 日志无 error），超时 10 min 报错并给手动指引
7. 完成页：提示 Ctrl+` / F4 可查看方案；「打开用户目录」按钮
```

### B8.1 实施结果与坑（2026-09-22）

| 项 | 结果 |
|----|------|
| 资源取齐 | 574.8MB（ghfast.top 代理全部命中；SDU 高校镜像备用） |
| 方案 id 核对 | `rime_ice` / `melt_eng` / `easy_en` / `hangeul2set` / `jaroomaji`；简繁开关 `traditionalization`（索引运行时扫描，不写死） |
| 语法模型 | LTS 版实为 **400MB**（计划里的"200MB 版"已不存在，AUR 也用同一个文件）；接入方式 = .gram 放用户目录根 + `<schema>.custom.yaml` 写 `grammar: language:` |
| **关键坑 1** | librime **只在用户目录根**找 `<schema>.schema.yaml`，不搜子目录 → 方案包必须**平铺**（原计划"独立子目录"不可行）；改用「平铺 + `.ai-voice-files.txt` 清单」保证卸载干净 |

| **关键坑 4** | 完成判定用「部署器退出码」而不是产物时间戳：librime 先写 `<schema>.schema.yaml` 再建词库表，只看产物会在词库表没建完时误判完成（曾把 easy_en 编译 kill 掉） |
| 实测 | 中文 16.0s / 日文 6.8~10.6s；`rime_ice.table.bin` 60.6MB、`jaroomaji.table.bin` 70.4MB、`easy_en.table.bin` 15.8MB |

## B10. 风险与对策

| 风险 | 影响 | 对策 |

| 首次部署编译大词库（日文 85 MB + 中文 49 MB）可能数分钟 | 用户以为卡死 | 向导进度提示 + 超时 10 min + 展示部署日志尾部 + 给手动部署指引 |

| 小狼毫升级/版本差异 | 兼容性 | 锁定 0.17.4；检测已装版本，低于要求则提示 |
| 日文/法文体验上限 | 用户预期 | 首启向导对日文加一句说明；法文二期 |
