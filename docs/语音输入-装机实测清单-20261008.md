## 阶段 2 · 热键健壮性（10 分钟，**本轮重点**）

> 这一阶段专门打历史故障：**"按了热键没反应"**。

| # | 操作 | 期望 | 我核对的日志判据 |
|---|------|------|----------------|
| 2.1 | **连续说 10 次**（每次一句话，间隔几秒） | 10 次全部出字 | `热键事件转发 Press` 条数 **==** `热键按下` + `会话中再次按下` 条数（不等就是有按下被吞） |
| 2.2 | 说一句长一点的（>15 字），**等它开始整理**（悬浮窗显示整理中），**立刻连按 3 次 F9 各说半句** | 3 次都进录音 | 同上对账 + `热键按下 …（… 滞后 Xms）` 里 X 应为 0 |
| 2.3 | 说一句 → 等 1 分钟完全静默（悬浮窗消失）→ 再按 F9 说 | 立即能录 | `会话开始`，无异常 |
| 2.4 | 切到别的输入法（Win+空格 换成微软拼音）打字几下 → 切回倾听输入法 → 按 F9 | 立即能录 | `挂起中收到热键：直接恢复并录音` |
| 2.5 | 连续压测：**快速点 10 下 F9**（不说法），再正常说一句 | 无卡死；最后那句正常出字 | `回调内自愈 KEYUP 丢失 N 次` —— **N 是多少都正常**（说明自愈在干活），关键是**后面那句仍能录** |
| 2.6 | 打开设置窗并**点一下别的地方**让焦点离开设置窗，再按 F9 | 正常录音 | ⚠️ **焦点在设置窗上时热键不响应是 Windows 限制**，不算 bug（见 §已知限制） |

## 阶段 6 · 噪声回归集录制（10 分钟，C1 前置）

> ⚠️ **必须先退出正在运行的倾听输入法**（托盘右键 → 退出程序），否则两个 F9 钩子并存，

## §已知限制（出现以下现象**不用报**）

| 现象 | 为什么 | 状态 |
|------|--------|------|
| 焦点在**本程序设置窗**上时按 F9 不响应 | Windows 对"输入目标是钩子进程自己的窗口"跳过钩子 | 系统限制，无法规避；设置窗隐藏到托盘后一切正常 |
| **管理员窗口**里按 F9 不出字 | UIPI 限制 | 与 Python 版一致 |
| **托管模式下托盘不变红** | 托盘属于 fork（WeaselServer），而 `ListenCtl STATUS` 只回 `starting/ready/suspended/disabled`，不含录音态 → **唯一反馈是悬浮窗** | 已知设计缺口（可补，待定） |
| 开机后**第一次**整理没洗稿 | llama-server 冷启动 10~25s，首次按设计降级直接出原文 | 设计如此 |
| `收集流错误: A buffer underrun or overrun occurred` | cpal 每会话开头偶发 | 已知，不影响识别（29 次实测均无丢字） |
| 纯噪声偶尔出几个字 | `saw_speech` 只能拦"整段纯噪声"，键盘/鼠标瞬变仍可能过门控 | **正在修（C1 VAD）** |
| 麦克风指示灯常亮 | 预热录音（`prewarm_capture`）设计如此 | 可关；空闲 10 分钟自动熄 |
